How attribution works

Windows tells you an app used the microphone. It rarely tells you which process, on whose behalf, or what else it touched. Intercept joins those signals into one local record and says where every field came from.

Updated 20 Nov 2026

·

Applies to 0.3.0-preview.19

·

6 min read

Overview

Intercept reads signals that Windows already records, joins them on the process that produced them, and keeps the source of every field. When a value can’t be established, the record says it is unknown and why, instead of guessing.

Identity by signature

Apps and agents are identified by their Windows publisher signature, package family or install path. A file name alone is never trusted: a renamed copy of claude.exe is just another program.

Services hosted inside svchost.exe are named individually, so a background service doesn’t hide behind its host process.

Signature checks run offline.

Intercept verifies the file or its Windows catalogue on your PC. It doesn’t contact a certificate or reputation service.

Agent lineage

When a signed agent starts other programs, Intercept records the chain from the agent to each descendant, resolved when each process starts. Processes are keyed by ID and start time, so a reused process ID can’t inherit an agent’s trust.

Sample lineage
claude.exe                      Anthropic, PBC ✓   agent root
└ node.exe                                         in lineage
└ pwsh.exe                                       in lineage
└ cargo.exe test --workspace                   logged
└ pwsh Get-Content ~/.ssh/config               guardrail

Claude: claude.exe → node.exe → pwsh, cmd or bash → git, cargo, npm or python

Codex: codex.exe → its sandbox helper → pwsh or cmd → tools

WSL: activity inside WSL is attributed to wsl.exe and marked “inside WSL, not itemised”

Computer use is attributed by session, recipient and time, not by lineage

Recipient and time don’t identify the sender.

During a computer-use session, another program typing into the same approved app looks identical. Intercept labels that input “allowed under the agent’s session”, never “typed by Claude”.

Confidence

Each record carries a confidence level, using the same labels as the app’s live feed.

Label

Meaning

Definite

Taken from a first-hand Windows record or a verified signature

Likely

Derived from a related record, for example a host name from DNS. The derivation is shown

Possible

A heuristic, such as the foreground app at the time. Never presented as fact

Unidentified

Not available. The record says why, for example that the process exited before lookup

Limits

Short-lived network connections can be missed between samples.

Host names inferred from DNS are marked as inferred.

Sensor records can be stale or absent on some Windows builds.

Encrypted contents, what a camera saw and what a microphone heard are never available.
