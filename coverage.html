Input routes

Software can reach an app in many ways. Intercept pauses only the route Windows flags as injected keyboard and mouse input. The others are reported as not paused, and are never folded into a “protected” claim.

For virtual input devices, Intercept classifies the device transport and counts virtual-keyboard events. That is detection, not blocking.

Blocked counts are guard decisions, not proof of delivery.

A receipt shows the guard asked for an event to be stopped. It doesn’t measure what the recipient finally received.

Guard limits

Same-user termination. Any program running as you can end a standard-user guard. The watchdog relaunches it within 2 s and records the gap with its cause.

Elevated windows. A standard-user guard can’t act on input aimed at elevated windows. The optional elevated guard, still in development, addresses this.

Hook renewal. Hooks are replaced every 30 seconds. Windows can remove a timed-out hook silently between renewals.

Earlier hooks. Another program’s hook earlier in the chain can handle an event before Intercept’s guard sees it.

Agent allowances

An allowance lets a trusted agent’s input through to an approved app during its session. Intercept always shows how strong the evidence was.

Allowances never apply to protected apps. When markers exist, a mismatch blocks the event and raises a medium finding. Without an active, calibrated session, an agent gets no allowance at all.
