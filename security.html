Trust and security

Security brief

What Intercept records on your PC, what it never records, which permissions it needs and how to check its claims. Written for security reviewers as well as everyday users.

Updated 20 Nov 2026

·

Applies to 0.3.0-preview.24

·

8 min read

At a glance

No telemetry

Intercept sends nothing about you or your PC to anyone. There is no account and no update checker.

Zero egress

Fonts are bundled, signature checks run offline, and enrichment comes only from files you import.

Never reads secrets

Credential and browser reviews read names, ages and permissions. Never passwords or cookie values.

Unsigned preview

Installers are not code-signed yet. Compare the SHA-256 published with each release before you run it.

Local by design

The desktop app works without a network connection. It keeps its history in your Windows profile and never trims it: migrations only add, and deleting anything you own takes a typed confirmation.

What is recorded

Intercept records metadata about activity, with the source of each field. It does not record content.

Recorded

Which app or process acted, with its publisher signature

When a camera or microphone was in use, from Windows’ own records

Which process connected where, with traffic per hour

Recipients and counts of software-generated input

Agent sessions: files changed, commands run and destinations

Never recorded

Typed key values or pointer coordinates

What a camera saw or a microphone heard

Passwords, cookie values or token contents

Encrypted network contents

Command argument values, except for flagged events, with secrets redacted

Permissions

Intercept runs as a standard user. Administrator rights are requested one feature at a time, only when you turn that feature on.

Administrator

Why

Monitoring, alerts and the input guard

Not needed

When turned on

Windows restricts these event providers to administrators

Background service

To install

Keeps recording while the app window is closed

Elevated input guard

In development

One-time consent

Sees input aimed at elevated windows and resists ordinary programs ending it

Input evidence

When the input guard decides on an event, Intercept keeps a receipt: the recipient app, timestamps, event counts and the decision. Receipts never contain key values or pointer coordinates.

A receipt names the recipient, not the sender.

It shows which app the input was aimed at and when. It cannot name the program that sent it, and a request to block is not proof of what the recipient received.

Trusted agents

Claude and Codex are trusted only when their Windows publisher signature verifies: Anthropic, PBC and OpenAI OpCo, LLC. A renamed or unsigned copy is treated like any other program.

An allowance for computer use activates only with signed-image evidence, a live session indicator calibrated for your Windows build, and an app you approved. A process name or a configuration file alone never activates one.

How agent attribution works

Locked findings

Five alerts never go quiet, for any agent and in any mode. You can mark a single event as expected for that path and agent; the guardrail itself stays on.

Reading a decoy credential file

Opening saved sign-ins: Credential Manager, browser logins, SSH keys or an agent’s token files

Adding or changing an MCP server, hook or plugin

Typing into a protected app

Turning off or tampering with Intercept’s protection

Verify a download

Compare the installer’s SHA-256 with the value published beside it before you run it.

PowerShell
# PowerShell
Get-FileHash .\Intercept-0.3.0-preview.24-x64-setup.exe -Algorithm SHA256
​
# Expected for Preview 24
579696792C938B21293E1A753A2F6381F11F444818A5821392CA0E1E244E4523

A matching checksum proves you have the published file. It does not prove who built it, because preview builds are not code-signed. Each release’s binary-provenance.json names the source commit it was built from.

Known limits

A program running as the same user can end a standard-user guard. The watchdog shortens and records the gap; it cannot prevent it.

Windows can silently remove a low-level hook that times out. Intercept renews its hooks and detects some failures, but cannot rule out a gap between renewals.

Only Windows-flagged keyboard and mouse injection can be paused. Touch, pen, virtual devices, accessibility actions and browser automation are reported as not paused.

Physical input trials and real-agent calibration have not been run for this preview.
