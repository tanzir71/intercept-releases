# Intercept 0.3.0-preview.16

Preview 16 adds reviewed lifecycle and guard-host controls to the Windows desktop app:

- Reviews collector backend changes before attempting the transition and retains approval and observed outcomes in personal action history. A failed transition requires a confirmed previous host; an uncertain outcome does not authorize another collector.
- Restores reviewed guard preferences when a new application session starts. Reconnecting Core or restarting the guard preserves the original application session and deadline. Later explicit Off choices remain effective.
- Reviews desktop quit with a ten-second Undo period and four restoration choices. Timed choices reopen the verified app after the original app and Core exit; Restart waits for another application session, and Never leaves affected controls paused.
- Supports reviewed selection of the Core session guard fallback while protection is Off and settings are compatible. Hook workers share exclusive ownership, and an active session blocker is retained while the standalone guard is unavailable.
- Retains Preview 15's history recovery, reviewed settings, service administration, sample/SRUM import approvals and responsive website fixes.

Full V5 remains unfinished. Collection recovery does not confirm that an installed Windows service is running or collecting. Saved protection requests and actual hook availability remain distinct. The desktop source remains private; this public repository distributes the website and installers.

This is an unsigned Windows 11 x64 prerelease. Native activation gates remain unchanged. Essential checks use fresh disposable profiles with input hooks disabled. Physical input/timing, actual installed-service switching, sign-in/elevation and SCM/UAC changes, real-agent AG-1 and the broad Windows matrix remain optional and unrun. Three failures from an earlier optional service-library run remain unresolved. Compare the published installer checksum before use.

Guard preference restoration on app restart uses storage v7; the reviewed session-host contract requires v8. First use raises the guard profile's minimum supported version. Older previews cannot reopen those settings after that upgrade; recorded collection history is retained. Profiles that do not use these features retain their earlier storage requirements.
