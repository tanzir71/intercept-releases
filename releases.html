0.3.0-preview.18

LatestPrerelease

20 Nov 2026 · Windows 11 x64

Preview 18 improves saved activity in Simple Alerts:

  • Repeated software-input findings now form live groups with recipient counts and plain explanations. Review opens the exact findings in Advanced mode; group Snooze uses one audited action with Undo. Locked guardrails stay outside routine quieting.
  • “Quiet the noise” suggestions use saved evidence for a known recipient. Suggestions change nothing until selected, and do not identify the sending program.
  • Recognised-agent history now searches and pages across retained history, with full saved counts and 50 events per page. Incoming and backdated activity do not shift the pages you are browsing; Reload includes newer activity.
  • Unavailable history shows an unknown count and an explicit reload action. It is not presented as zero activity or a complete list from the latest snapshot.
  • Older saved events open by their exact IDs. Recognised activity remains in history, and recipient/time evidence is not promoted into proof of who sent input.
  • Undoing an EasyPrivacy conversion now supports long history paths while retaining the supplied source and converted bytes.

This preview retains the reviewed firewall, cleanup, decoy, backend, guard-host and desktop-exit controls from earlier previews. Full V5 and the remaining handover/design audit are still unfinished.

The desktop source remains private. This public repository distributes the website, installers, release notes and checksums. The Windows 11 x64 installer is unsigned; compare its published SHA-256 before installation.

Essential release checks use the optimized paired binaries and packaged app in fresh disposable profiles with collection paused and input hooks disabled. They do not install over your app or change your Windows services, registry, credentials or sign-in setup. Physical input/timing, real-agent calibration, actual installed-service switching, SCM/UAC and sign-in trials, and broad Windows/large-history matrices remain optional and unrun. Missing calibration does not enable a native protection route.

Existing guard storage requirements remain unchanged: features introduced in earlier previews can require storage v8, which older previews cannot reopen. Recorded collection history is retained.

0.3.0-preview.17

Prerelease

19 Nov 2026 · Windows 11 x64

Preview 17 improves reviews and recovery for local actions:

  • Firewall block, Undo and recovery use the shared V5 review, with Cancel focused, a one-second key debounce and checks against the selected rule, service and history. Rule readback remains distinct from proof that traffic was blocked.
  • Privacy and cleanup reviews retire when history or write authority changes. Lost acknowledgements retire the attempted token and direct you to saved actions before another review.
  • Cookie selection distinguishes the same site in different browser profiles. Cleanup reviews one profile at a time and keeps its encrypted backup metadata durable before changing the cookie database.
  • Decoy creation and removal retain ownership of the selected Windows file through changes and rollback. A replacement file cannot inherit an earlier removal approval.
  • A decoy creation has a ten-second Undo notice and a permanent entry in both ledger views. Undo opens a fresh typed DELETE 1 review, checks the original file identity and retains the creation and compensating removal. Older creation records without that identity retain manual typed removal.
  • The Windows service explicitly refuses personal decoy file actions; use desktop collector mode for those changes.

This preview retains the reviewed backend, guard-host and desktop-exit controls from Preview 16, along with the responsive landing page and documentation fixes. Full V5 and the remaining handover audit are still unfinished.

The desktop source remains private. This public repository distributes the website, installers, release notes and checksums. The Windows 11 x64 installer is unsigned; compare its published SHA-256 before installation.

Essential release checks use the optimized paired binaries and packaged app in fresh disposable profiles with collection paused and hooks disabled. They do not install over your app or change your Windows services, registry, credentials or sign-in setup. Physical input/timing, real-agent calibration, actual installed-service switching, SCM/UAC and sign-in trials, and broad Windows/large-history matrices remain optional and unrun. Three failures from an earlier optional service-library run remain unresolved. Missing calibration does not enable a native protection route.

Existing guard storage requirements remain unchanged: features introduced in earlier previews can require storage v8, which older previews cannot reopen. Recorded collection history is retained.

0.3.0-preview.16

Prerelease

19 Nov 2026 · Windows 11 x64

Preview 16 adds reviewed lifecycle and guard-host controls to the Windows desktop app:

  • Reviews collector backend changes before attempting the transition and retains approval and observed outcomes in personal action history. A failed transition requires a confirmed previous host; an uncertain outcome does not authorize another collector.
  • Restores reviewed guard preferences when a new application session starts. Reconnecting Core or restarting the guard preserves the original application session and deadline. Later explicit Off choices remain effective.
  • Reviews desktop quit with a ten-second Undo period and four restoration choices. Timed choices reopen the verified app after the original app and Core exit; Restart waits for another application session, and Never leaves affected controls paused.
  • Supports reviewed selection of the Core session guard fallback while protection is Off and settings are compatible. Hook workers share exclusive ownership, and an active session blocker is retained while the standalone guard is unavailable.
  • Retains Preview 15's history recovery, reviewed settings, service administration, sample/SRUM import approvals and responsive website fixes.

Full V5 remains unfinished. Collection recovery does not confirm that an installed Windows service is running or collecting. Saved protection requests and actual hook availability remain distinct. The desktop source remains private; this public repository distributes the website and installers.

This is an unsigned Windows 11 x64 prerelease. Native activation gates remain unchanged. Essential checks use fresh disposable profiles with input hooks disabled. Physical input/timing, actual installed-service switching, sign-in/elevation and SCM/UAC changes, real-agent AG-1 and the broad Windows matrix remain optional and unrun. Three failures from an earlier optional service-library run remain unresolved. Compare the published installer checksum before use.

Guard preference restoration on app restart uses storage v7; the reviewed session-host contract requires v8. First use raises the guard profile's minimum supported version. Older previews cannot reopen those settings after that upgrade; recorded collection history is retained. Profiles that do not use these features retain their earlier storage requirements.

0.3.0-preview.14

Prerelease

19 Nov 2026 · Windows 11 x64

  • Adds On restart to reviewed standalone protection-Off requests. Protection restores when Intercept reopens after the original app exits. Core reconnects, guard restarts and a second app opened alongside the original preserve the Off choice. A later explicit Off cancels restoration.
  • Shows pending restoration in Home, the guard summary and the tray, with its approval retained in the existing actions Ledger.
  • Adds an Off-only, reviewed upgrade from the legacy Core guard to the standalone guard. Existing settings are preserved, and pending restoration schedules prevent an unsafe handoff. Running desktop and recovery hosts adopt the authenticated guard without restarting.
  • Connects service-mode status and emergency input release to the interactive user's guard. A service outage can open input-only recovery. Complete service-mode reviewed actions, history and Undo remain unavailable.
  • Improves Core shutdown and recovery so acknowledgements drain before exit and an ambiguous request is not repeated.
  • Keeps the responsive landing-page and documentation improvements, including readable attribution diagrams at tablet widths.

This is an unsigned Windows 11 x64 prerelease. Existing physical, recipient, agent and Windows build calibration requirements still apply. This release does not establish passing native calibration. Physical input/timing, actual sign-in/elevation, real-agent AG-1 and Windows build matrices remain optional and unrun. Compare the installer checksum before use.

App-restart restoration uses profile storage v6. Once used, that profile retains v6 after restoration because its immutable journal contains the new metadata. Downgrading a used v6 profile is unsupported. Existing profiles that do not use this choice retain their earlier storage requirements.

Full V5 remains in progress. Reverse host selection, complete service-mode reviewed transactions/Ledger/Undo, remaining lifecycle/elevation and action/design parity are still open. The original completion deadline is unchanged.

Prerelease

19 Nov 2026 · Windows 11 x64

  • Improves recipient identification for child windows, owned popups and packaged Windows apps, with window-event cache updates and process-creation checks.

Prerelease

18 Nov 2026 · Windows 11 x64

0.3.0-preview.11

Prerelease

18 Nov 2026 · Windows 11 x64

Windows 11 x64 prerelease. The desktop source repository remains private; binary-provenance.json identifies the exact source commit and installer bytes. The public tag identifies this distribution repository's commit.

  • Current native computer-use status is shared across protection, simple/advanced agents, Home and the advanced overview. Saved coding sessions remain separate. Recipient permissions expire independently from session indicators; stale or disconnected evidence is unavailable.
  • Native callback decisions connect calibrated current sessions, eligible recipients, bounded recording and authenticated durable metadata receipts. Protected-recipient input has a separate receipt path, and locked alerts can import while ordinary collection is paused.
  • Codex configuration-derived recipients require exact installed identity and a calibrated app-ID/image mapping. Configuration changes revoke the previous generation. Policy review, checked panel Undo and preservation of dirty drafts remain available.

Actual signed-image evidence and a guard/build-bound AG-1 calibration record are required before native agent allowances can activate. No passing real-agent calibration was created for this release. Recipient/time evidence retains an unknown sender and does not prove input delivery. The installer is unsigned; compare the published SHA-256 before use. Both matching Core and guard are included; downgrading a used storage-v4 profile is unsupported.

Production native/UI builds and exact package binding passed. Thirteen isolated policy API checks and eleven packaged GUI checks passed with collection paused and hooks unarmed. Fifteen focused UI cases and the indexed-lookup check passed. The public page passed desktop/mobile checks with 485 loaded images, 41 links, seven FAQs and no external renderer requests. These are focused checks; they do not establish physical input behavior.

Broad regression, physical input/timing, real-agent AG-1, Windows/elevation/sign-out matrices, S29–S36 and large-history acceptance remain optional and not run. UI metadata fixtures do not count as calibration.

Full V5 is unfinished. Remaining work includes the legacy allowance command's verified flow, global/permanent agent-policy Undo, lifecycle/service/quit recovery, elevation plumbing, recipient prewarming/UWP handling, away-return UX, durable daily health totals and remaining action/design parity. The original 24-hour target elapsed; usable previews and repository updates continue.
